# Доработка архитектуры SIP TICD: двухсторонние инварианты и анализ их устойчивости во времени

**Дата:** 23 ноября 2026 г.  
**Исходная модель:** `sip/ticd_recalibrated.py` (фиксация нормировки на обучающей норме).  
**Новая реализация:** `sip/ticd_temporal_invariants.py`, `MultiScaleInvariantTICD`.  
**Эксперимент:** `experiments/compare_sip_ticd_multiscale.py`.  
**Выполненный Actions:** [#45237816494](https://github.com/verge88/signal_network_sim_v2/actions/runs/45237816494), `success`.

## 1. Причина изменения

В предыдущем успешном эксперименте с TICD, обученной на нормальных
данных SIP-имитации после ограниченной калибровки по настоящим записям
LTE-A Linphone, при FPR ≈0,52% модель достигала средней полноты
25,32%, но **не обнаруживала ни статистическую, ни адаптивную
компрометацию**. В исходной архитектуре нормированное к единице
нарушение транзакционных инвариантов смешивалось с контекстным
и консенсусным сигналами, что существенно ослабляло прямое
рассогласование отчётности и фактического состояния SIP-транзакций.

## 2. Новая модель

Пусть `dcr(t,i)` и `ddr(t,i)` — доли завершённых и незавершённых
диалогов по отчётности i-го узла, `p_ack(t,i)` — независимо
полученное мастером отношение транзитных ACK к ответам 200 OK.
Все три компонента уже существовали в симуляторе; **поля
с метками атак и истинным состоянием `gt_*` не используются**.

Направленные остатки закона сохранения транзакционного состояния:

```
r_minus(t,i) = max{0, 1 - dcr(t,i) - ddr(t,i)};
r_plus(t,i)  = max{0, dcr(t,i) + ddr(t,i) - 1}.
```

`r_minus` — недоучтённое замыкание, характерное для
статистической/адаптивной маскировки в изучаемом имитационном сценарии;
`r_plus` — избыточная отчётность, характерная для примитивного
нарушителя.

Независимый остаток ACK:

```
r_ACK(t,i) = max{0, dcr(t,i) - p_ack(t,i)}.
```

Учитываются только доставленные контрольные ответы:
при `cu_delivered=0` мгновенные остатки умножаются на ноль.

Симулятор поддерживает ранее существовавшую, вычисляемую на
мастерском узле каузальную историю `mean_txn_state_consistency_error`,
то есть среднюю величину `abs[1-(dcr+ddr)]` по не более чем
30 последним наблюдениям соответствующего узла.
Это **не скользящее среднее по тестовому пакету**:
история формируется при последовательном моделировании до оценки
данного наблюдения. Для реальной эксплуатации требуется такой же
онлайн-учёт истории, которого внешние PCAP не содержат.

Для каждого остатка `r_j` величина `q99_j` определяется **только
по нормальной обучающей выборке** (не менее `1e-3` во избежание
нулевого знаменателя). Итоговая оценка выбранной архитектуры:

```
E_instant(t,i) = max{
    clip(r_minus / q99_minus, 0, 50),
    clip(r_plus / q99_plus,   0, 50),
    clip(r_ACK  / q99_ACK,    0, 50)
}
E_temporal(t,i) = max{
    E_instant(t,i),
    0.85 * clip(mean_txn_error / q99_mean, 0, 50)
}
```

Проанализированы четыре варианта: `instant`, `temporal`,
`temporal_zone` и `temporal_hybrid`. Два последних также
учитывают относительное зональное отклонение и прежнюю TICD.
На независимой **разработочной** синтетической выборке выиграл
наименее сложный вариант `temporal` (победа по заранее заданной
полноте статистического и адаптивного воздействия с ограничением FPR).
Зональная и контекстная ветви сохранены в коде как абляционные
варианты, **но не входят в выбранную модель**.

Порог каждого варианта устанавливается по 99-му процентилю
оценок отдельной нормальной проверочной имитации; тестовые
метки и тестовое распределение не участвуют в подгонке.

## 3. Проект эксперимента

Только **частичная внешняя калибровка** параметров симулятора по
условным долям INVITE/ACK/BYE из 16 реальных PCAP Di Mauro:
архив SHA-256 `e455d66eef30d9399ba3beefc36ad2a4a7e2fac0684aa1ae405a30a2371af9a7`.
Другие параметры симуляции — топология, потери, атакующие сценарии,
состояние СУ и зональная отчётность — **не калибровались на реальной
эксплуатационной сети**.

| Набор | Seed | Объект |
|---|---|---|
| Обучение | 1101, 1102 | 7920 нормальных наблюдений |
| Настройка порога | 1201, 1202 | 7920 нормальных наблюдений |
| Выбор архитектуры | 1301, 1302 | Независимые имитации с атаками |
| Финальное тестирование | 1401–1405 | 19800 наблюдений; 5325 атак, 14475 норм |

Все прогоны имеют длительность 2 часа, шаг 20 с. Начальные значения
генератора различаются, но **структура, типы и временные пропорции
атак у разных прогонов совпадают**. Следовательно, это тест
обобщения по случайным реализациям симулятора, а не независимая
валидация на новых типах атак или реальных операторах.

Изначальный FrozenReferenceTICD и новая TICD обучаются на одних
и тех же нормальных данных и получают пороги с одних и тех же
нормальных проверочных прогонов. Сравнение проводится на
**идентичных финальных тестовых записях**, которые до выбора
архитектуры не использовались. Выбор самой архитектуры использует
разметку атак на `1301,1302`: поэтому полностью
«обучением без меток атак» корректно называть только подгонку
параметров нормального детектора, а не весь процесс выбора структуры.

## 4. Полученные результаты — неизменённая тестовая выборка

| Метрика | FrozenReferenceTICD | MultiScaleInvariantTICD (temporal) |
|---|---:|---:|
| ROC-AUC | **0,885982** | 0,798428 |
| PR-AUC | 0,726622 | **0,774290** |
| F1 | 0,394702 | **0,745829** |
| Полнота (recall) | 25,1831% | **61,2770%** |
| FPR | **0,8912%** | 1,1192% |
| Истинноположительные (TP) | 1341 | 3263 |
| Ложноположительные (FP) | 129 | 162 |
| Истинноотрицательные (TN) | 14346 | 14313 |
| Ложноотрицательные (FN) | 3984 | 2062 |

При близком бюджетном FPR, настроенном только на нормальной
валидации, новая TICD обнаружила дополнительно **1922 атакующих
наблюдения**, допустив дополнительно **33 ложные тревоги**.
Это улучшение выбранной рабочей точки, **не универсальное
улучшение ранжирования**: ROC-AUC заметно снизилась.

| Компрометация узла | FrozenReferenceTICD | Новая TICD |
|---|---:|---:|
| Примитивная (n=1390) | 86,76% | 99,71% |
| Статистическая (n=1080) | 0,19% | 99,91% |
| Адаптивная (n=775) | 0,52% | 100,00% |

Важно: 775 строк адаптивного класса — это **пять повторений одного
сконструированного сценария**, а не 775 независимых компрометаций.
Показатели в таблице не определяют реальную чувствительность на
полевых SIP-сетях.

## 5. Артефакты

Сохранены `ticd_multiscale_model.pkl` с моделью прежней и
новой архитектур и их порогами, `comparison_report.json`,
`architecture_manifest.json`, данные отдельных имитационных
прогонов `*.csv.gz`, калибровочный манифест по реальным SIP-трассам
и `multiscale_environment.txt`. Программа верифицировала
успешную обратную загрузку и независимость вычисления оценок от
объёма оцениваемого пакета.

**Научное ограничение.** Полученные показатели описывают
валидность алгоритма **в рамках заданной имитационной модели**.
Предполагаемый компрометированный узел в этих сценариях
маскирует отчётность так, что возникает наблюдаемый дефицит I1.
При иной стратегии нарушителя, состоянии линий или схеме
размещения доверенного наблюдателя сигнал может исчезнуть.
Проверка на реальных независимых синхронных отчётах узлов
и магистральных SIP-захватах по-прежнему не выполнена.
