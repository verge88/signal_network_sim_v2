# Ролевое ограничение ранних SIP-предупреждений TICD: формализация и эксперимент

**Состояние исследования:** 24 ноября 2026 г.  
**Основа:** замороженная двухуровневая TICD с ранее обученным физическим и каузальным ACK-каналами.  
**Программная реализация:** `sip/ticd_role_scoped_warning.py`.  
**Методика:** `experiments/evaluate_ticd_role_scoped_warning.py`.  
**Рабочий процесс:** `.github/workflows/sip-ticd-role-scoped.yml`.

## 1. Диагностический анализ прежних ложных предупреждений

Результаты независимого экспериментального исследования
`ZonalWarningTICD` были проверены в
[GitHub Actions #45252940147](https://github.com/verge88/signal_network_sim_v2/actions/runs/45252940147).
Нормальная контрольная выборка и разработочная выборка
не гарантировали переносимость установленной частоты
ложных предупреждений в обычные сценарии атак.

Отдельная, заведомо **исследовательская (post hoc)**
проверка 
[GitHub Actions #45345156303](https://github.com/verge88/signal_network_sim_v2/actions/runs/45345156303)
повторно прочитала ранее опубликованные имитационные
сценарии, но **не меняла обученную модель и пороги**.

Из 169 ложных предупреждений выбранной зональной TICD
в обычном сценарии:

| Тип SIP-функции | Ложные предупреждения |
|---|---:|
| Шлюз пользовательских агентов `UA_GW` | **162** |
| Сервер перенаправления `REDIRECT` | 5 |
| Сервер регистрации `REGISTRAR` | 2 |
| Прокси-сервер `PROXY` | 0 |

На `UA_GW` приходилось **162/169 = 95,86%**
предупреждений об имитационных доброкачественных узлах.
Причём в модели нет оснований автоматически отождествлять
эту статистику с неисправностью одного-единственного
экземпляра `UA_GW` или реальным сетевым инцидентом:
строки принадлежат зависимым временным рядам разных узлов.

В ранее выполненном имитационном сценарии слабой
компрометации при потерях ×10 все 335 предупреждений
об атакующих наблюдениях возникли на функциях `PROXY`.
Это наблюдение допускает новую **проверяемую гипотезу**:
для поиска именно скрытой компрометации SIP-прокси
ранние предупреждения целесообразно формировать в
предметной области операторских прокси-функций, а
не для любого участника SIP.

**Методическое разграничение:** все старые seed
использованы только для выявления слабого места и
формулирования гипотезы. Критерии выбора следующей
модели и итоговый результат не определяются
по этим уже известным тестовым меткам.

## 2. Архитектура и математическая формализация

Пусть в момент времени `t` для узла `i` из
доверенного инвентаря оператора известна роль
`r_i ∈ {PROXY, REDIRECT, REGISTRAR, UA_GW}`.

Два замороженных канала формируют оценки:

```
A_i(t) = S_LossConditionedPhysicalTICD(i,t)
C_i(t) = S_CausalACK(i,t)
```

Для варианта зональной коррекции рассматривается
заранее определённая оценка `C_i^z(t)`.
Используется только физически наблюдаемый мастерский
ACK-дефицит и синхронный зональный срез; при поправке
на медианную SIP-нагрузку дополнительно участвуют
потенциально недоверенные отчёты узлов, и это
отдельно оговорено как слабое место.

Пусть `R` — **заранее выбранный набор допустимых
типов SIP-функций для раннего предупреждения**.
Тогда решающая функция:

```
L_i(t) =
  2, если A_i(t) > theta_A;
  1, если A_i(t) <= theta_A
         и r_i принадлежит R
         и C_i(t) > theta_W(R);
  0, иначе.
```

Для каждого `R` проверяется отдельная нормальная
условная калибровка `theta_W`, а порог
`theta_A` и функция `A_i(t)`
**во всех моделях полностью одинаковы**.

Параметры тревоги на нормальных проверочных данных:

```
theta_A = max_{m ∈ {1,3,5,10,15}}
          Q_0.99[A | benign, loss=m]

theta_W(R) = max_{m ∈ {1,3,5,10,15}}
          Q_0.995[C | benign, loss=m,
                     A<=theta_A, r ∈ R]
```

Таким образом, выбранный допустимый уровень
ложных предупреждений на **нормальной валидации**
не должен превышать 0,5% доли доброкачественных
строк. Это *эмпирический контроль*, не гарантия
для всех эксплуатационных нагрузок, зон и атак.

Соответственно:

```
FPR_alert = FP_alert / N_benign

FWR_warning = FP_warning_only / N_benign

Recall_alert = TP_alert / N_attack

Incremental_warn = TP_warning_only / N_attack

Coverage_any = Recall_alert + Incremental_warn
```

**`Coverage_any` не является полнотой
подтверждённого обнаружения**.
Само определение уровня 2 означает лишь
более высокую статистическую уверенность,
а не факт расследованной и доказанной атаки.

## 3. Проверяемые альтернативы

Рассмотрены два уже обученных канала предупреждения:

- `raw`: исходная каузальная история дефицита ACK;
- `zone_load`: та же история с ранее заданной
  зональной поправкой на медианную SIP-нагрузку.

Для каждого канала оцениваются четыре режима доступа
к предупреждениям:

| Вариант | Какие узлы получают предупреждения |
|---|---|
| Без ограничения | `PROXY`, `REDIRECT`, `REGISTRAR`, `UA_GW` |
| Без шлюзов | `PROXY`, `REDIRECT`, `REGISTRAR` |
| Только прокси | `PROXY` |
| Прокси и регистрация | `PROXY`, `REGISTRAR` |

Всего восемь кандидатных решений.

Сильные тревоги обоих каналов не должны
изменяться, как и ранее обученные параметры
замыкания SIP-диалогов, нормировка физического
ACK-дефицита и каузальная история.

## 4. Разделение выборок и предопределённая функция выбора

| Набор | Seed | Назначение |
|---|---|---|
| Доброкачественная нормальная проверка | 31101–31502 | Настройка `theta_A` и `theta_W` для пяти режимов потерь |
| Разработочная имитационная выборка | 32101–32602 | Выбор типа предупреждения, допустимых ролей и оценка устойчивости |
| Новая итоговая выборка | 33101–33903 | Только независимая оценка выбранного варианта |

В каждом нормальном режиме потерь
`×1, ×3, ×5, ×10, ×15` используется
по два независимых имитационных прогона
длительностью 2 часа.

Разработочная выборка — 12 прогонов
с обычными атаками, скрытым перенаправлением
×5/×10/×15/×20 и правдивой отчётностью
скомпрометированных узлов.

Окончательный тест — 27 **новых**
двухчасовых имитационных прогонов:
обычные атаки, слабое перенаправление
при потерях ×5/×10/×15/×20, правдивая
отчётность, полностью доброкачественный
трафик при потерях ×1/×7/×20.
Никакой из этих seed не использовался
в прежних исследованиях TICD.

Заранее зафиксирован критерий:

```
J(R) = 0.15*I_stat(loss5)
     + 0.25*I_stat(loss10)
     + 0.25*I_stat(loss15)
     + 0.25*I_stat(loss20)
     + 0.10*I_all(truthful)
     - 12*max(FWR_default-0.005, 0)
     - 5*SUM_s max(FWR_s-0.005, 0)
     - 0.5*mean_s FWR_s
```

Здесь `I_stat` — **дополнительный охват
предупреждениями** статистически
замаскированной компрометации прокси,
а не подтверждённая полнота.

Функция предназначена исключительно
для выбора кандидатной архитектуры на
разработочной **синтетической** выборке.
К итоговым метрикам она не подгоняется.

## 5. Проверки корректности

Эксперимент должен подтвердить:

- отсутствие общих seed между всеми
  предыдущими и новыми исследованиями;
- отсутствие доступа к `gt_*`, меткам атак,
  истинному состоянию компрометации и
  нормальным событиям при формировании решения;
- неизменность статуса сильной тревоги
  при любом ограничении ролей;
- воспроизводимость результатов на
  произвольной подвыборке записей после
  полного формирования зонального среза;
- перезагрузку зафиксированного классификатора;
- раздельный учёт ложных предупреждений,
  сильных ложных тревог, полноты уровня 2
  и дополнительного предупреждающего охвата.

В итоговой оценке используются отдельные
имитационные seed, а не независимость
каждого двадцатисекундного отсчёта.

## 6. Существенное ограничение обобщаемости

**Ролевое ограничение — намеренное изменение
области обнаружения.** Если оставить
предупреждения только на `PROXY`, то
скрытая компрометация шлюза `UA_GW`,
помимо сохранившегося сильного канала,
не сможет сформировать *раннее*
предупреждение. Поэтому нельзя называть
такое изменение универсальным
улучшением обнаружения компрометации всех
SIP-функций.

Используемый имитатор создаёт скрытую
компрометацию именно прокси. Возможный
высокий результат для `PROXY` необходимо
воспринимать как доказательство только
**в рамках этой модели угроз**,
но не для произвольного атакуемого узла.

16 независимых LTE-A SIP PCAP Di Mauro
использовались исключительно для частичной
калибровки частот INVITE/ACK/BYE
доброкачественного трафика. Синхронные
мастерские физические счётчики, полные SIP
зоны, действительные потери и
подтверждённые реальные атаки
в этих источниках отсутствуют.

## 7. Результаты независимого имитационного эксперимента

[GitHub Actions #45345567415](https://github.com/verge88/signal_network_sim_v2/actions/runs/45345567415)
завершился успешно. Все 8 вариантов, 10
нормальных проверочных прогонов, 12
разработочных прогонов и 27 полностью
новых независимых тестовых прогонов
обработаны в едином воспроизводимом
конвейере.

После выбора только на разработочных
данных принята модель
**`no_gateway_zone_load`**,
т. е. ранние предупреждения только

`REDIRECT` с ранее зафиксированной
поправкой на медианную нагрузку зоны.
Сильные тревоги остаются доступны
для **любых** SIP-ролей.

В использованной нормальной проверочной
выборке зафиксированы:

| Параметр | Значение |
|---|---:|
| Порог сильной тревоги | 1,143219343666418 |
| Порог раннего предупреждения выбранного варианта | 0,8424342791526883 |
| Максимальный FPR сильной тревоги на нормальной валидации | 0,9470% |

Это **эмпирические** характеристики
имитационной нормальной валидации,
а не вероятностные эксплуатационные
гарантии.

### 7.1. Частота ложных предупреждений

На финальных тестовых прогонах модели
сравнивались **попарно**: одинаковые
исходные наблюдения, одна и та же
сильная тревога и её порог,
только разные разрешённые роли
и условная обработка предупреждения.

| Имитационный сценарий | Исходный неограниченный канал, FWR | Ролевой канал, FWR | FPR сильных тревог у обоих |
|---|---:|---:|---:|
| Обычные атаки | 1,497% | **0,104%** | 0,576% |
| Слабая компрометация, потери ×5 | 0,194% | **0,082%** | 0,950% |
| Слабая компрометация, потери ×10 | 0,375% | **0,203%** | 0,699% |
| Слабая компрометация, потери ×15 | 0,212% | **0,121%** | **1,454%** |
| Слабая компрометация, потери ×20 | 0,192% | **0,121%** | **1,173%** |
| Правдивая отчётность | 0,669% | **0,162%** | 0,517% |
| Только нормальные данные, потери ×1 | 0,497% | **0,202%** | 0,631% |
| Только нормальные данные, потери ×7 | 0,564% | **0,354%** | 0,968% |
| Только нормальные данные, потери ×20 | 0,320% | **0,177%** | **1,599%** |

Отдельно: на обычном сценарии
снижение FWR составило
**1,393 процентного пункта**, или
приблизительно **в 14,4 раза**.
Сильная тревога в контрольном
и предложенном вариантах
осталась **строго идентичной**
по каждому тестовому прогону.

**Отрицательный результат не скрывается:**
при высоких потерях ×15 и ×20
FPR сильных тревог превышает 1%.
Ролевая ветвь изменяет только
предупреждения и **не может
устранить эти сильные ложные тревоги**.
Это отдельная задача улучшения
калибровки физического канала.

### 7.2. Сохранение чувствительности к статистической маскировке

Следующая таблица показывает исключительно
**дополнительную долю атакующих наблюдений,
получивших предварительное предупреждение**,
а не полноту сильных тревог:

| Слабое скрытое перенаправление | Неограниченные предупреждения | Ролевые предупреждения |
|---|---:|---:|
| Потери ×5 | 25,70% | **25,70%** |
| Потери ×10 | 43,95% | **43,95%** |
| Потери ×15 | 49,38% | 48,60% |
| Потери ×20 | 46,60% | 46,30% |

Иными словами, для испытанных
прокси-атак при потерях ×10
дополнительный охват **не снизился**,
а при ×15 и ×20 уменьшился
менее чем на 1 процентный пункт.

В сильном канале при потерях ×20
полнота обнаружения именно
статистически замаскированной
компрометации составляла **44,75%**.
Пример общего охвата
`44,75% + 46,30% ≈ 91,05%`
следует называть **охватом
тревогами и предупреждениями**,
не полнотой подтверждённого
обнаружения.

### 7.3. Научная интерпретация

Выбранная конструкция отвечает
специализированной модели угроз
«скрытая компрометация SIP-прокси».
Высокие ложные предупреждения
на доброкачественных шлюзах
пользовательских агентов не
включаются в предупреждающий
канал, поэтому в имитационном
эксперименте существенно снижается
операторская нагрузка.

Но это **не универсальный детектор
компрометации любого SIP-узла**.
Реальные или синтетические атаки
с компрометацией `UA_GW` в
целевой проверке слабой
прокси-компрометации не
моделируются. При таком воздействии
устройство может сформировать
сильную тревогу, однако функция
раннего предупреждения намеренно
отключена для этого класса.

Улучшение подтверждено только
на новых **имитационных**, а не
операторских данных. Отдельные
прогоны генератора не равны
независимым реальным трассам:
они разделяют математические
предположения об ACK, потере
пакетов и механизмах компрометации.
