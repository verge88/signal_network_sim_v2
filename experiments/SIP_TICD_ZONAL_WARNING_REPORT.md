# TICD: исследование зональной контекстной нормировки предупреждений

**Этап:** очередная проверка двухуровневой TICD для SIP.  
**Программная реализация:** `sip/ticd_zonal_warnings.py`.  
**Эксперимент:** `experiments/evaluate_ticd_zonal_warnings.py`.  
**Воспроизводимый CI:** [TICD zonal-context early-warning heldout comparison](https://github.com/verge88/signal_network_sim_v2/actions/workflows/sip-ticd-zonal-warning.yml).

## 1. Мотивация

Предыдущий эксперимент `TwoTierSIPTICD` сформировал две
взаимоисключающие категории: сильная тревога по инвариантному
и физическому ACK-каналу и предупреждение по каузальной истории
дефицита ACK. Он подтвердил высокий **дополнительный охват
синтетической статистически замаскированной компрометации**,
но выявил непереносимость отдельного порога предупреждений:
при целевом FWR=0,5% на чистой нормальной валидации
в обычном сценарии с атаками FWR составил 1,739%.
Независимый аудит показал превышение целевого уровня
во всех трёх имитационных прогонах.

Это значит, что высокочувствительный временной сигнал
необходимо оценивать с учётом режима локальной зоны сети.
При этом прежний физический детектор и
**порог сильной тревоги должны оставаться общими** для
всех сравниваемых моделей, иначе эффект новой
предупреждающей ветви был бы смешан с изменением уровня 2.

## 2. Наблюдаемые данные и доверие

Для каждого узла `i`, зоны `z` и интервала `t`
ранее обученная `CausalPersistentACKTICD`
возвращает два **замороженных** признака:

- `A_i(t)` — оценка сильной тревоги на основании
  инвариантов I1/I2 и физически наблюдаемого отклонения ACK/200,
  нормированная по уровню потерь и типу узла.
- `C_i(t)` — каузальная оценка накопленного за шесть
  интервалов дефицита физического ACK.

Дополнительный зональный срез вычисляется в одном временном
интервале по всем доступным контролируемым узлам:

```
M_z(t) = median_{j in z} C_j(t)
L_z(t) = median_{j in z} obs_total_messages_j(t)
P_z(t) = median_{j in z} cu_combined_loss_prob_j(t)
```

`M_z` опирается на мастерское измерение ACK и
связанный с ним ранее обученный детектор.
`P_z` отражает оценку состояния канала
контрольного взаимодействия, а не прямые
потери SIP-пакетов.

**Принципиальное ограничение `L_z`:**
`obs_total_messages` — передаваемая узлом
отчётность о нагрузке, **не обязательно
доверенный физический счётчик**. Участник
атаки способен подменять этот показатель;
медиана служит лишь ограниченной защитой
от *меньшинства* скомпрометированных узлов.
Поэтому модель не может считаться
устойчивой к согласованному контролю
большинства участников зоны.

Для реализации в сети необходим буфер
полного синхронного среза зоны.
Зональная медиана должна вычисляться
**до** индивидуальной оценки строк;
вычисление её заново на произвольном
подмножестве тестовых записей запрещено,
так как создаёт зависимость от состава пакета.

## 3. Сравниваемые архитектуры

Пусть `k` — коэффициент подавления общего
зонального фона, а `L_ref` — медиана
зональной нагрузки, определённая
**только на нормальной обучающей выборке**.

Проверяются следующие преобразования
предупреждающего сигнала:

```
W_base_i(t) = C_i(t)

W_peer_i(t;k) = max[0, C_i(t)-k*M_z(t)]

H_z(t;k) = 1+k*max[0, L_z(t)/L_ref-1]

W_load_i(t;k) = C_i(t)/H_z(t;k)

W_joint_i(t;k) = W_peer_i(t;k)/H_z(t;k)
```

Для `peer`, `load` и `joint` оцениваются
`k=0.5` и `k=1.0`. Для зоны с единственным
узлом зональное вычитание не применяется,
так как отсутствуют сравнимые соседние узлы.

Все формулы основаны на текущем и
предыдущем доверенном наблюдении
канала и синхронном срезе соседей;
ни `gt_*`, ни `is_anomaly`, ни
`attack_type`, ни истинный статус
компрометации не входят в функцию оценки.

## 4. Независимая калибровка порогов

Сильная тревога во всех вариантах
определяется одинаково:

```
Alert_i(t) = [A_i(t)>theta_A]

theta_A = max_{m in {1,3,5,10,15}}
                Q_0.99(A | benign_m)
```

Раннее предупреждение зависит от выбранного
зонального преобразования `W`:

```
Warn_i(t) =
  [A_i(t)<=theta_A] AND [W_i(t)>theta_W]

theta_W = max_{m in {1,3,5,10,15}}
   Q_0.995(W | benign_m, A<=theta_A)
```

Предельная доля ложных предупреждений
на предусмотренной нормальной
проверочной выборке не более 0,5%;
это **эмпирическое** свойство именно
этого набора, а не вероятностная
гарантия для новых зон и сценариев.

Важное отличие от полного переобучения:
параметры ранее обученных физических
и временных TICD **не изменяются**.
Обучается только опорный масштаб
`L_ref` для нового зонального контекста.
Коэффициент `k` и вариант архитектуры
выбираются **на других имитационных
разработочных сценариях**.

## 5. Выбор архитектуры без утечки из теста

| Назначение | Seed | Потери и условия |
|---|---|---|
| Нормальная обучающая выборка | 21101–21502 | 1×, 3×, 5×, 10×, 15×; по два запуска |
| Нормальная проверочная выборка | 22101–22502 | Те же пять режимов, другие seed |
| Разработочная выборка | 23101–23502 | Обычные атаки, слабая компрометация ×10/×15/×20, правдивая отчётность; по два запуска |
| Итоговая отложенная выборка | 24101–24903 | Девять сценариев, по три полностью новых seed |

Итоговые сценарии: обычные атаки,
слабое скрытое перенаправление при потерях
×5/×10/×15/×20, правдивая отчётность
скомпрометированного узла, а также
**полностью нормальный трафик** при
×1/×7/×20 потерях.

До создания итоговых данных
фиксируется функция выбора варианта:

```
J = 0.25 * incr_stat(weak10)
  + 0.25 * incr_stat(weak15)
  + 0.20 * incr_stat(weak20)
  + 0.10 * incr_all(truthful)
  + 0.20 * incr_all(default)
  - 18 * max(0, FWR_default - 0.005)
  - 8  * SUM_s max(0, FWR_s - 0.01)
  - 3  * max(0, FPR_union_default - 0.015)
```

`incr` — доля атакующих наблюдений,
получивших **только предупреждение
после исключения сильных тревог**.
Метрика `J` используется исключительно
на разработочной синтетической выборке.
Если ни один зональный вариант
не выигрывает у исходной двухуровневой
TICD, победителем остаётся исходный вариант;
**не допускается выбор по итоговому тесту**.

## 6. Обязательные проверки

В GitHub Actions проверяются:

1. Отсутствие пересечений использованных
   ранее и новых обучающих, проверочных,
   разработочных и тестовых seed.
2. Отсутствие обучения по размеченным
   атакующим данным и сохранение
   прежнего физического/каузального
   детектора без изменения.
3. Совпадение решений на подвыборке с
   решениями для соответствующих строк
   полной *предварительно обработанной*
   синхронной зональной выборки.
4. Неизменность оценок после удаления
   всех симуляторных скрытых истинных
   показателей `gt_*` и меток атак.
5. Совпадение сильных тревог и их FPR
   для сравниваемых вариантов, поскольку
   их сильный канал идентичен.
6. Раздельные оценки доли сильных ложных
   тревог, ложных предупреждений,
   общего FPR всех сигналов,
   подтверждённой полноты и
   дополнительного охвата предупреждениями.
7. Подсчёт эпизодов ложных предупреждений
   отдельно по узлам и по каждому seed.

**Сильная тревога** — решение с более
строгим порогом, а не подтверждённый факт
компрометации. Отдельное раннее
предупреждение нельзя включать в её
полноту без указания собственного FWR.

## 7. Ограничения научной интерпретации

Единственная внешняя калибровка имитатора
по реальным SIP PCAP Di Mauro
охватывает доли нормальных
INVITE/ACK/BYE. Сами профили потерь,
состояние СУ, физические ACK-потоки,
зональная нагрузка и действия
скомпрометированных узлов
**не измерялись по независимым
операторским трассам**.

Изменение распределения нормальной
нагрузки при наличии атак может
повышать ложные предупреждения на
формально доброкачественных узлах
в тех же зонах. Такие события
допускают два толкования:
ложная локальная тревога или
реальная вторичная сетевая реакция
на соседнюю атаку. В отчёте
используются метки имитатора
**для диагностического разделения
после теста**, но не для
оценивания или выбора модели.

## 8. Фактические результаты

Результаты будут внесены из успешно
выполненного GitHub Actions и
`zone_context_ticd_report.json`,
без предварительного предположения
