# Условная нормировка TICD при росте фоновых потерь в SIP-сети

**Дата:** 23 ноября 2026 г.  
**Код:** `sip/ticd_loss_conditioned.py`, `experiments/evaluate_sip_ticd_loss_adaptive.py`  
**CI:** [GitHub Actions — loss-adaptive TICD](https://github.com/verge88/signal_network_sim_v2/actions/workflows/sip-ticd-loss-aware.yml)  
**Основа:** сохранённая `PhysicalClosureTICD(mode="physical")`, обученная в предыдущем эксперименте [#45239668351](https://github.com/verge88/signal_network_sim_v2/actions/runs/45239668351).

## Постановка задачи

В предыдущей проверке нормальный уровень ложных тревог
`PhysicalClosureTICD` при пятикратном повышении потерь достигал
**4,117%**, хотя проверочный порог для обычной нагрузки задавался
на уровне около 1%. Это показывает непереносимость фиксированного
порога к изменению параметров физического канала.

Основная цель настоящего эксперимента — корректировать масштаб
оценки **только по доверенному измеряемому признаку потерь**
и дополнительным **доброкачественным обучающим прогонам**,
не используя метки и распределение тестового трафика.

Наблюдаемая мастером вероятность потери отчётов СУ
`cu_combined_loss_prob` — **не точный физический показатель
потери SIP-сообщений**. В имитационной модели оба показателя
строятся по связанным сетевым путям, что делает её возможным
объясняющим признаком. В реальной эксплуатации соответствие
этого показателя потерям SIP необходимо устанавливать
отдельными натурными измерениями.

## Архитектура

Исходная `PhysicalClosureTICD` вычисляет прежний показатель
`S_phys(t,i)` по физической доле ACK/200 и направленным
транзакционным инвариантам. Её параметры **заморожены**.

Дополнительный модуль изучает распределение этого показателя на
доброкачественном трафике при различных фонах потерь:
`L_i(t) = cu_combined_loss_prob_i(t)`. На нормальной обучающей
выборке строятся границы равномассовых классов уровня потерь
`B(L)` (не более 8 классов), отдельно оцениваются квантиль
`Q_{0.99}(S_phys | B)` и, в абляционных вариантах, такой
же квантиль для сочетания `(B, тип узла)`. Для малых подгрупп
предусмотрено объединение с общим квантилем класса.

Нормированная оценка:

```
S_cond(t,i) = S_phys(t,i)
    / max{0.001, Q_0.99[S_phys | B(L_i(t)), node_type_i]}.
```

Обобщённая формула включает вариант без `node_type` и вариант
с регуляризованным смешиванием специфического и общего
квантилей нормального трафика. Наличие `node_type` в
функции оценки не раскрывает компрометацию:
это эксплуатационно известный тип SIP-узла.

Конечный порог каждого кандидата фиксируется по нормальным
**проверочным** прогонам со множителями физических потерь
`1, 3, 5, 10`:

```
theta = max_{m in {1,3,5,10}}
         Q_0.99[S_cond(X_validation, benign, loss_multiplier=m)].
```

Таким образом, ни один из предусмотренных нормальных
проверочных режимов не превышает приблизительно 1% FPR.
Этот расчёт **не гарантирует** такого же FPR при новых
значениях потерь, топологиях или нагрузках.

## Разбиение

| Назначение | Симуляционные seed |
|---|---|
| Обучение нормальной условной нормировки | 4101–4402: по 2 запуска при 1×, 3×, 5×, 10× |
| Проверочная норма для порога | 5101–5402: по 2 запуска на режим |
| Разработка/выбор варианта архитектуры | 6101–6402: по 2 запуска на сценарий |
| Итоговая проверка, не участвующая в выборе | 7101–7603: по 3 запуска в 6 сценариях |

Разработочные сценарии: основной, слабое скрытое перенаправление
при ×5 потерь, правдивая отчётность скомпрометированного узла,
слабое перенаправление при ×10 потерь. Для выбора структуры
используются **метки атак только разработочных прогонах**.
В имитационном тесте предусмотрены те же семейства, но
с другими seed, а также два новых чисто доброкачественных
режима с потерями **×7** и **×15**. Множитель ×15 находится
за верхней границей обучающих режимов и намеренно проверяет
предел экстраполяции.

Сравниваются четыре группы: исходная физическая TICD
с прежним рабочим порогом, она же с единым консервативным
порогом для разных фоновых потерь, исходная временная TICD,
и три кандидата условной нормировки (`loss`,
`loss_node`, `loss_node_shrink`). В итоговой таблице
фиксируется кандидат, выбранный **до** запуска теста,
а не лучший результат задним числом.

Модульные проверки дополнительно запрещают обучение
по строкам с меткой атаки и гарантируют отсутствие
зависимости оценки от состава тестового пакета.

## Ограничения интерпретации

1. Калибровка SIP-симулятора по 16 реальным
   LTE-A PCAP Di Mauro остаётся **частичной**:
   только доли методов INVITE/ACK/BYE. Ни CU-канал,
   ни потери сети не калиброваны независимыми реальными
   измерениями.
2. Синхронные доверенные журналы компрометированных SIP-узлов
   отсутствуют в опубликованных независимых наборах.
   Результаты настоящего эксперимента относятся только
   к *имитационным* атакам и тестовым фондам потерь.
3. Разделение по seed исключает буквальное повторное
   использование случайной реализации, но все прогоны
   принадлежат одной модели генерации; строки внутри
   отдельного прогона статистически зависимы.
4. Полная модель временной инвариантной TICD должна
   получать последовательную мастерскую телеметрию,
   и её текущий симулятор оценивает сам, а не измеряет
   настоящая SIP-сеть.
5. Калибратор не перенастраивается на тестовых
   потоках, так как такая перестройка может дать
   искажённую оценку и уязвима к отравлению нарушителем.
