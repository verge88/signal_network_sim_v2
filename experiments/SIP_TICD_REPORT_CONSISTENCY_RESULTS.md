# TICD для SIP. Согласованность отчёта CU и независимый аудит

Входная единица решения — один ведомый узел за один 20-секундный интервал. Уровни 0, 1, 2 означают отсутствие сигнала, предупреждение и подтверждённую тревогу соответственно. Полнота учитывает только уровень 2.

## Расчёт

Базовый канал — зафиксированная версия `frozen_block` с измеряемыми потерями транспорта и эталоном, полученным при отдельной пусконаладочной записи. Дополнительно проверяются доли девяти методов SIP, включая категорию OTHER. Сумма долей, доля преобладающего метода и отношение INVITE/ACK должны согласовываться с полями того же доставленного отчёта. Параметр `ratio_resolution` задаёт шаг округления доли. При двух противоречивых отчётах за последние шесть интервалов формируется подтверждённая тревога. Потерянный отчёт не добавляет свидетельств, а отказ первичного наблюдателя очищает его историю.

Отдельный канал получает число проверенных операций и число расхождений с разрешённым состоянием. Для наблюдения из `n` проверок с `k` расхождениями приращение равно `k·ln(0.045/0.013) + (n−k)·ln(0.955/0.987)`. Это фиксированные параметры данного имитационного эксперимента. Тревога возникает при сумме выше 9 за 16 интервалов или выше 12 за 32 интервала. Пустая выборка даёт нулевое приращение. В интервале без текущей выборки аудит не выдаёт тревогу. Для самостоятельного подтверждения базовому каналу нужны доступные активные и пассивные измерения в текущем интервале и не менее чем в 80% наблюдаемых интервалов последнего окна длины 32. Требуются как минимум три подтверждения этого канала за пять интервалов. Контроль отчёта и аудит способны выдать самостоятельную тревогу.

## Применение сохранённой модели

В артефакте `sip-ticd-report-consistency-model` находятся проверенная сериализованная модель, версия исходного кода и список Python-зависимостей. В окружении Python 3.11 с указанными зависимостями добавьте каталоги `sip` и `experiments` из соответствующего коммита в путь импорта. Пример для запуска из корня репозитория.

```python
import pickle
import sys
from pathlib import Path

sys.path[:0] = [str(Path("sip").resolve()), str(Path("experiments").resolve())]
with open("report_consistency_ticd.pkl", "rb") as src:
    model = pickle.load(src)

levels = model.predict_levels(observations, commissioning)
```

`observations` содержит физические измерения из `ticd_measured_loss.RAW`, доли методов CU, наблюдаемые отношения и счётчики аудита. Полная схема указана в `COLUMNS` сценария оценки. `commissioning` содержит отдельную нормальную запись того же узла и установки. Для каждого ряда нужны уникальные ключи установки, узла и интервала. При шаге представления долей 0,01 задайте `model.ratio_resolution = 0.01`. При воспроизведении обработки подавайте полную доступную историю узла до момента решения. Равенство решений при усечении будущей истории проверяется в CI.

## Интерпретация

Метод использует избыточность агрегатов в отчёте CU и доступность независимого аудита. В контрольном варианте с полностью согласованным отчётом гистограмма нормируется, а агрегаты пересчитываются из той же гистограммы. В результате вклад проверки отчётов исчезает. При одинаковых наблюдениях в латентном и нормальном состояниях решения совпали. Метрики характеризуют имитационные сценарии. Полевая проверка на размеченном трафике оператора остаётся открытой.
