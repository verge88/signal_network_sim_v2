# Двухуровневая архитектура обнаружения SIP-аномалий TICD

**Версия исследования:** 24 ноября 2026 г.  
**Программная реализация:** `sip/ticd_two_tier.py`  
**Экспериментальный протокол:** `experiments/evaluate_ticd_two_tier.py`  
**Воспроизводимость:** `.github/workflows/sip-ticd-two-tier.yml`

## 1. Обоснование архитектуры

В предыдущих исследованиях `LossConditionedTICD` имела
относительно низкую частоту ложных тревог, но
недостаточную полноту обнаружения статистически
маскируемого скрытого перенаправления SIP при
значительных потерях. Дополнительный каузальный
канал накопления физического дефицита ACK/200
повысил полноту на новых имитационных выборках,
но повысил FPR в обычных условиях с 0,47–0,79%
до 1,62–1,97%.

Из этой противоречивой картины **не следует**,
что раннее предупреждение нужно считать равным
тревоге высокой уверенности. Предлагается
сохранить две отдельные точки решения с
**собственными долями ложноположительных
срабатываний**, а не искусственно улучшать
полноту объединением несопоставимых уровней.

## 2. Математическая постановка

Для узла `i` и текущего интервала времени
`t` определены две оценки, построенные
по независимым мастерским наблюдениям:

- `S_inst(i,t)` — ранее обученная
  `LossConditionedTICD` по физически
  наблюдаемым ACK/200, инвариантам I1/I2
  и условной нормировке по потерям и типу
  SIP-узла;
- `S_causal(i,t)` — нормированная
  экспоненциальная история физического
  дефицита ACK за 6 интервалов по 20 с,
  рассчитанная строго по текущим и прошлым
  наблюдениям данного узла.

Исходные параметры обоих каналов
**заморожены** и повторно не подгоняются
на новом тесте.

Обозначим через `theta_A` порог сильной
тревоги, через `theta_W` — отдельный
порог предупреждения. Решающая функция:

```
L(i,t) =
    2,  если S_inst(i,t) > theta_A;
    1,  если S_inst(i,t) <= theta_A
              и S_causal(i,t) > theta_W;
    0,  иначе.
```

Уровни: `2` — тревога высокой уверенности,
`1` — предварительное предупреждение
(не подтверждённая тревога),
`0` — отсутствие сигнала.

Оба уровня взаимоисключающи:
`P(L=1 & L=2)=0` по определению.

На каждой отдельной **нормальной проверочной**
имитационной выборке с фоновыми потерями
`m ∈ {1,3,5,10,15}`
вычисляется квантиль `Q_0.99` исходной
мгновенной оценки. Порог `theta_A` —
максимум этих пяти квантилей. Тем самым
порог сильной тревоги не зависит от
атакующих или тестовых меток.

При фиксированном `theta_A` порог
предупреждения `theta_W` определяется
по записям нормальных проверочных
наборов **без сильной тревоги**.
Для заранее заданного бюджета
`β_W ∈ {0.005,0.01,0.02,0.03}`
вычисляется:

```
theta_W(β_W) = max_m
   Q_(1 - β_W) [
     S_causal(i,t) | benign_m,
     S_inst(i,t) <= theta_A
   ].
```

Из-за строгого сравнения `>`
в каждом предусмотренном режиме
валидации частота ложных предупреждений
не превышает заданный `β_W`.
Это свойство выборки калибровки,
**не гарантия для новых режимов потерь**.

Обоснованное различение метрик:

```
FPR_alarm = FP_alarm / N_benign
FWR_warning = FP_warning_only / N_benign
FPR_any_signal = (FP_alarm + FP_warning_only) / N_benign

Recall_alarm = TP_alarm / N_attack
Coverage_warning_extra = TP_warning_only / N_attack
Coverage_any = (TP_alarm + TP_warning_only) / N_attack
```

В частности, `Coverage_any` **нельзя**
именовать «полнотой подтверждённого обнаружения»
или использовать как замену `Recall_alarm`.

Дополнительно подсчитывается количество
непрерывных эпизодов ложных тревог и
ложных предупреждений по отдельным узлам
внутри имитационных прогонов. Один эпизод
может включать несколько последовательных
20-секундных строк.

## 3. Источник данных и независимость разбиений

Данный эксперимент опирается на ранее
построенный имитатор, чьё **условное**
распределение нормальных SIP INVITE/ACK/BYE
частично калибровано по 16 несинтетическим
LTE-A PCAP Di Mauro. Контрольная сумма
архива: `e455d66eef30d9399ba3beefc36ad2a4a7e2fac0684aa1ae405a30a2371af9a7`.
Ни реальные скомпрометированные узлы,
ни физические потери SIP-транзита,
ни независимые контрольные отчёты СУ
по этим PCAP **не калиброваны**.

| Этап | Начальные значения симулятора | Использование меток атак |
|---|---|---|
| Нормальная проверочная выборка | 13101–13502 | Отсутствуют, только выбор порогов |
| Разработочные имитационные атаки | 13601–13902 | Только выбор бюджета предупреждений |
| Полностью отложенный итоговый тест | 14101–14903 | Только расчёт итоговых метрик |

Каждый проверочный режим нормальных потерь
`×1, ×3, ×5, ×10, ×15` содержит по два
отдельных двухчасовых прогона. Разработочные
сценарии содержат по два прогона для обычных
атак, слабого перенаправления при потерях
×10 и ×15 и сценария правдивой отчётности
скомпрометированного узла.

Итоговая проверка охватывает по три
полностью новых двухчасовых прогона
в девяти условиях: обычные атаки,
слабое перенаправление при потерях
×5, ×10, ×15, ×20, правдивая отчётность,
только нормальная нагрузка при потерях
×1, ×7 и ×20. В качестве приблизительно
независимой единицы статистического анализа
используется имитационный прогон, а
**не каждая его 20-секундная строка**.

## 4. Критерии проверки

В итоговом отчёте обязательны:
отдельная частота ложных тревог,
отдельная частота ложных предупреждений,
суммарная частота сигналов, полнота
тревог и дополнительный охват
предупреждениями; показатели по
статистической, примитивной и
адаптивной маскировке; парные сравнения
по одним и тем же тестовым seed.

Новый вариант **не считается улучшением
подтверждённых тревог**, если при
одинаковом пороге их полнота не меняется:
ранние предупреждения — отдельная
аналитическая возможность, имеющая
собственную стоимость ложных сигналов.

Проверяются сохранение/повторная
загрузка обученного классификатора,
отсутствие пересечения выборок,
неизменность решения при произвольном
перемешивании или усечении уже
вычисленного потока мастерской телеметрии.

## 5. Научные ограничения

Оба канала используют модельно
связанные физический ACK-дефицит
и потери СУ, но связь между ними
не проверена на реальном операторском
SIP-трафике. Высокая имитационная
полнота не может доказывать обнаружение
реальной компрометации.

Даже тревога уровня 2 лишь имеет
более строгую нормальную рабочую точку;
она **не является юридически или
фактически подтверждённым фактом
компрометации узла**. Это различие
существенно для безопасности
эксплуатационной диагностики.

## 6. Фактические результаты

[GitHub Actions #45249660732](https://github.com/verge88/signal_network_sim_v2/actions/runs/45249660732)
завершился **успешно**. Исходная ранее
обученная каузальная TICD была загружена
из зафиксированного артефакта
`#45247020460`; исходные нормирующие
коэффициенты не изменялись. Выполнены
проверки сохранения и повторной загрузки
двухуровневой модели, однозначности
классов и независимости решения от
состава тестового пакета.

В новом эксперименте использованы
10 отдельных нормальных проверочных
прогонов (39 600 наблюдений),
8 разработочных прогонов с имитационными
атаками и **27 новых тестовых
прогонов** в девяти режимах по
11 880 наблюдений каждый.
Статистической независимости 106 920
тестовых строк друг от друга не
предполагается: единицей повторения
служит отдельный прогон/seed.

По четырём заранее определённым
бюджетам предупреждений
`β=0,5%;1%;2%;3%` на разработочной
выборке выиграл самый строгий
**β=0,5%**.

Фактически зафиксированы:

| Параметр | Значение |
|---|---:|
| Порог сильной тревоги `theta_A` | 1,2102398884 |
| Порог предупреждения `theta_W` | 0,8344744355 |

**Это только выборочные показатели валидации**,
не теоретические гарантии обобщения на
новые нагрузки и сетевые потери.

| Уровень потерь | Доля сильных тревог | Дополнительно отдельные предупреждения | Общий охват |
|---|---:|---:|---:|
| ×5 | 68,48% | +31,52 п.п. | 100,00% |
| ×10 | 51,42% | +47,98 п.п. | 99,40% |
| ×15 | 49,33% | +48,59 п.п. | 97,93% |
| ×20 | 42,44% | +51,69 п.п. | 94,13% |

Эта таблица демонстрирует реальную
для изучаемой **имитационной модели**
ценность предварительного предупреждения.
Но `99,40%`, `97,93%`
и `94,13%` — именно **охват сигналами**,
а не полнота подтверждённых атак.
Исходная полнота сильной тревоги
при ×20 остаётся всего **42,44%**.

### 6.4. Нестабильность доли ложных предупреждений

В обычном тестовом сценарии получено
**1,739% ложных предупреждений**,
хотя на доброкачественной проверочной
выборке максимально было 0,4924%.
Превышение примерно в **3,53 раза**
указывает на недостаточную переносимость
нормального предупреждающего порога
между выборками или сценариями.
Тестовые показатели **не использовались**
для изменения этого порога после
расчёта — отрицательный результат
сохранён без попытки подгонки.

В возможной системе эксплуатации
отдельный предварительный сигнал
должен сопровождаться процедурой
проверки, корреляции с другими
измерениями и ограничением частоты
уведомлений. Нельзя утверждать,
что дополнительный охват атак
предоставляется без дополнительных
ложных срабатываний.

### 6.5. Сравнение с прежним порогом сильной тревоги

Консервативная нормальная перекалибровка
порога **не изменяет обученную
архитектуру сильной тревоги**.
На обычном тестовом сценарии FPR
снизился с 0,484% (прежний порог)
до 0,322%, при полноте 69,80%
против 69,77%.
На слабом перенаправлении ×20
FPR снизился с 1,267% до 0,920%,
но полнота тревог — с 80,95%
до 78,56%. Это допустимая
цена более консервативного
решения в данном имитационном
эксперименте; её нельзя
интерпретировать как улучшение
качества по всем метрикам.

**Итог:** двухуровневое решение
разделяет сильные тревоги и
высокочувствительные предупреждения
без скрытого смешивания их FPR.
На синтетических слабых атаках
оно обеспечивает большой
дополнительный охват, но
не подтверждает одинаково низкий
FWR во всех условиях и не
устраняет необходимость внешней
валидации TICD на настоящих
многоточечных захватах и
доверенной SIP-телеметрии.
