# Независимая проверка каскада Diameter

Workflow **Diameter external cascade validation** восстанавливает базовый каскад
и каскад с повторяемостью отчётов из первого прогона десятисидовой серии
(`45599697858`). Первый прогон выбран по номеру. Сценарий сверяет контрольные
суммы трёх обучающих и калибровочных выборок, профиля калибровки трафика и
соответствие вычисленных порогов сохранённым. Артефакт
`diameter-frozen-cascade` содержит модели, предпроцессинг, пороги и перечень
56 входных признаков. Используйте артефакт из доверенного запуска и ту же среду
(`versions.txt`).

## Входные данные

Для каждой независимой сессии подготовьте три файла.

1. Исходный PCAP или PCAPNG независимого стенда либо оператора.
2. Экспорт наблюдений управляющего узла. Одна строка на узел и каждый
   запланированный 15-секундный опрос, включая пропуски (`cu_delivered=0`).
   Столбцы `node_id`, `interval` и все признаки из `model.json`.
   Командные доли берутся из реально полученного CU-отчёта. Поля зоны,
   задержки, целостности и статистики окон рассчитываются в той же семантике,
   что у исследуемого метода. Код типа узла задаётся по
   `node_type_encoding` из `model.json`.
3. Независимая разметка из журнала эксперимента или подтверждённых инцидентов.
   CSV содержит только `node_id,interval,label` с метками `benign`,
   `compromise` либо `exclude` для окон, исключённых протоколом эксперимента.
   Разметка покрывает все экспортированные окна, включая прогрев и пропуски.
   Метки фиксируются до расчёта оценок детектора.

Сверьте время PCAP, расписания CU и журнала разметки до передачи в оценщик.
Задокументируйте начало интервала 0 по UTC, охват узлов, происхождение отчётов
и разметки в `source`. Проверка файлов и SHA-256 защищает от случайного
повтора входных данных. Происхождение трасс, синхронизацию часов и семантику
экспортированных признаков подтверждает протокол сбора.

Пример структуры `cascade-manifest.json`:

```json
{
  "data_origin": "independent_testbed",
  "window_seconds": 15,
  "sessions": [
    {
      "id": "session-01",
      "source": "Описание стенда, времени начала, наблюдения CU и журнала эпизодов",
      "capture": "session-01/diameter.pcap",
      "features": "session-01/cu_features.csv",
      "labels": "session-01/ground_truth.csv"
    }
  ]
}
```

Значения `data_origin` — `independent_testbed` или `operator`. Отдельные
сессии должны быть независимыми. Используйте штатную нагрузку с устойчивыми
профилями и пропусками опросов. Для оценки полноты нужны подтверждённые или
контролируемые и заранее размеченные аномалии в системе отчётности. Не храните
операторскую телеметрию в публичных артефактах.

## Оценка

```sh
python diameter/diameter_external_cascade.py evaluate \
  --model frozen/cascade.joblib --manifest external/cascade-manifest.json \
  --out external-results.json
```

Отчёт включает полноту по 15-секундным окнам, FPR на штатных окнах, полноту по
эпизодам и медиану задержки по обнаруженным эпизодам. Эпизод — непрерывная
последовательность размеченных окон компрометации на одном узле. Для проверки
прироста приведён парный 95%-й бутстрэп-интервал по независимым сессиям, если
хотя бы в пяти сессиях есть окна соответствующего класса. При отсутствии
размеченных эпизодов полнота и задержка остаются неопределёнными (`null`).
