# Внешняя проверка SS7-модели на реальных данных

## Назначение

`ss7/validate_real_cdr.py` выполняет независимую проверку внешней валидности
канонической модели ОКС-7 (`ss7/fix.py`) на **несинтетической** мобильной
нагрузке.

Исходное происхождение данных:

- Telecom Italia, **Telecommunications - SMS, Call, Internet - MI**;
- Harvard Dataverse, DOI **10.7910/DVN/EGZHFV**;
- данные получены из реальных CDR сети Telecom Italia в Милане.

Для автоматического CI используется публичное зеркало
`GreatLove/CellularTrafficPrediction` на Hugging Face. Оно уже агрегирует
исходные CDR по ячейке и времени и содержит реальные поля `sms-in`,
`sms-out`, `call-in`, `call-out`, `internet`.

Harvard Dataverse 6.10 требует Guestbook Response для прямой API-загрузки этого
набора. В CI намеренно не передаются вымышленные имя/e-mail; поэтому workflow
использует публичное зеркало с сохранением ссылки на исходный DOI и SHA-256
файла зеркала.

## Что проверяется

Публичного размеченного набора реальных SS7-атак, сопоставимого с входами
канонической модели, в открытом доступе нет. Эта проверка поэтому **не
измеряет recall, precision или AUC реальных атак** и не выдаёт CDR за
пакетную SS7-трассу.

Проверяются:

1. перенос распределений доступных признаков с нормальной синтетической
   SS7-нагрузки на независимую реальную мобильную нагрузку;
2. доля реальных окон, отвергаемых Isolation Forest как аномальные при пороге,
   откалиброванном только на нормальной синтетической validation-части;
3. величина synthetic-to-real domain shift по статистике Колмогорова—Смирнова
   и покрытию реальных значений 99%-м диапазоном синтетической нормы.

## Какие признаки восстанавливаются

Из зеркала непосредственно наблюдаются входящие/исходящие SMS и вызовы.
Поэтому используются только признаки, для которых не требуется синтезировать
неизвестные пакетные события:

- `total_messages`;
- `mtype_entropy`;
- `map_share`;
- `isup_share`;
- `in_out_ratio`.

Активность CDR не считается буквальным числом MSU. Для согласования с
каноническими шаблонами сервисов используются условные сигнальные единицы:
вызов — пять типов ISUP, исходящее SMS — одна MAP-операция, входящее SMS —
две MAP-операции.

Не наблюдаемые в агрегированном CDR зеркале признаки исключаются, а не
синтезируются: DPC-направления и их энтропия, `transit_share`,
`dlg_closure_ratio`, все кросс-узловые инварианты и `integrity_fail`.

## Профили проверки

- `full_proxy`: пять доступных признаков, включая масштаб
  `total_messages`;
- `ratio_proxy`: четыре безразмерных признака без `total_messages`, что
  уменьшает влияние различия единиц измерения CDR и модельных счётчиков.

Для каждого профиля JSON содержит:

- `target_synthetic_fpr`;
- `synthetic_test_fpr`;
- `real_rejection_rate_unlabeled`;
- `median_ks_stat`;
- `median_real_inside_synth_99pct`;
- `median_abs_shift_sigma`;
- `transfer_warning`;
- сдвиг по каждому признаку.

`transfer_warning=true` означает существенный внешний доменный разрыв. Это
диагностика переносимости, а не оценка обнаружения реальных атак.

## Запуск

```bash
python -m ss7.validate_real_cdr \
  --date 2013-11-01 \
  --max-bytes 67108864 \
  --max-real-windows 60000 \
  --output results/ss7_real_cdr_validation.json
```

Workflow: `.github/workflows/ss7-real-cdr-validation.yml`.

Артефакт: `ss7-real-cdr-validation`.
