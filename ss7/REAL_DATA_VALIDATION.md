# Внешняя проверка SS7-модели на реальных данных

## Назначение

Скрипт `ss7/validate_real_cdr.py` выполняет независимую проверку внешней
валидности канонической SS7-модели (`ss7/fix.py`) на **несинтетических**
телекоммуникационных данных.

Источник данных — публичный набор Telecom Italia:

- **Telecommunications - SMS, Call, Internet - MI**
- Harvard Dataverse
- DOI: **10.7910/DVN/EGZHFV**
- исходные данные получены из реальных CDR сети Telecom Italia, Милан, 2013 г.

GitHub Actions получает файл непосредственно из Harvard Dataverse. В репозиторий
не добавляются копии исходного набора.

## Что именно проверяется

Публичного размеченного набора реальных SS7-атак, сопоставимого с входами модели,
нет. Поэтому эта проверка **не измеряет recall/precision атак** и не выдаёт CDR за
пакетную SS7-трассу.

Проверяются две вещи:

1. переносимость распределений признаков с синтетической нормальной SS7-нагрузки
   на независимую реальную мобильную нагрузку;
2. доля реальных окон, которые Isolation Forest, обученный только на нормальных
   данных канонической модели, отвергает как аномальные при пороге, заданном на
   синтетической validation-части.

Это позволяет обнаружить доменный разрыв и оценить риск ложных срабатываний на
реальной нагрузке.

## Наблюдаемые признаки

Из CDR напрямую доступны интенсивности входящих/исходящих SMS и вызовов, время,
ячейка и код страны контрагента. Для проверки используется только подмножество
признаков `OWN`, для которого есть внешне наблюдаемый аналог:

- `total_messages`;
- `mtype_entropy`;
- `dest_entropy`;
- `n_unique_dest`;
- `dest_top1_ratio`;
- `dest_top2_ratio`;
- `map_share`;
- `isup_share`;
- `in_out_ratio`.

Код страны используется только как прокси разнообразия направлений и **не
приравнивается к DPC**. Активность CDR также не считается буквальным числом MSU:
она переводится в условные сигнальные единицы по шаблонам сервисов модели
(вызов — пять типов ISUP; исходящее SMS — одна MAP-операция; входящее SMS —
две MAP-операции).

Не наблюдаемые в CDR признаки (`transit_share`, `dlg_closure_ratio`,
кросс-узловые невязки, integrity channel) исключаются, а не синтезируются.

## Почему используется префикс файла

Один суточный файл Harvard Dataverse превышает 300 MB. Для CI скачивается
ограниченный байтовый префикс реального файла (по умолчанию 64 MiB), после чего
отбрасывается только последняя незавершённая строка. Значения строк не
генерируются и не модифицируются. В JSON-отчёте сохраняются ID файла, размер
скачанной выборки и SHA-256 полученного префикса.

## Интерпретация результата

В отчёте формируются два профиля:

- `full_proxy` — все доступные прокси-признаки;
- `ratio_proxy` — в основном безразмерные признаки, менее чувствительные к
  различию единиц измерения между CDR и SS7-счётчиками.

Для каждого профиля выводятся:

- целевой FPR на синтетической validation-части;
- фактический FPR на независимой синтетической test-части;
- `real_rejection_rate_unlabeled` на реальных CDR;
- статистика Колмогорова—Смирнова по признакам;
- доля реальных значений внутри 99%-го диапазона синтетической нормы;
- признаки с максимальным доменным сдвигом.

`transfer_warning=true` — диагностический признак существенного
synthetic-to-real разрыва. Он не является оценкой качества обнаружения атак.

## Запуск

```bash
python -m ss7.validate_real_cdr \
  --date 2013-11-01 \
  --max-bytes 67108864 \
  --output results/ss7_real_cdr_validation.json
```

GitHub Actions workflow: `.github/workflows/ss7-real-cdr-validation.yml`.
Результат публикуется как artifact `ss7-real-cdr-validation`.
