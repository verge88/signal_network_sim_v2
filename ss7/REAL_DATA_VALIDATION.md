# Внешняя проверка SS7-модели на реальных данных

## Назначение

`ss7/validate_real_cdr.py` выполняет независимую проверку внешней валидности
канонической модели ОКС-7 (`ss7/fix.py`) на **несинтетической** мобильной
нагрузке.

Исходное происхождение данных:

- Telecom Italia, **Telecommunications - SMS, Call, Internet - MI**;
- Harvard Dataverse, DOI **10.7910/DVN/EGZHFV**;
- данные получены из реальных CDR сети Telecom Italia в Милане.

Для автоматического CI используется публичное зеркало
`GreatLove/CellularTrafficPrediction` на Hugging Face. Оно уже агрегирует
исходные CDR по ячейке и времени и содержит реальные поля `sms-in`,
`sms-out`, `call-in`, `call-out`, `internet`.

Harvard Dataverse 6.10 требует Guestbook Response для прямой API-загрузки этого
набора. В CI намеренно не передаются вымышленные имя/e-mail; поэтому workflow
использует публичное зеркало с сохранением ссылки на исходный DOI и SHA-256
файла зеркала.

## Что проверяется

Публичного размеченного набора реальных SS7-атак, сопоставимого с входами
канонической модели, в открытом доступе нет. Эта проверка поэтому **не
измеряет recall, precision или AUC реальных атак** и не выдаёт CDR за
пакетную SS7-трассу.

Проверяются:

1. перенос распределений доступных признаков с нормальной синтетической
   SS7-нагрузки на независимую реальную мобильную нагрузку;
2. доля реальных окон, отвергаемых Isolation Forest как аномальные при пороге,
   откалиброванном только на нормальной синтетической validation-части;
3. величина synthetic-to-real domain shift по статистике Колмогорова—Смирнова
   и покрытию реальных значений 99%-м диапазоном синтетической нормы.

## Какие признаки восстанавливаются

Из зеркала непосредственно наблюдаются входящие/исходящие SMS и вызовы.
Поэтому используются только признаки, для которых не требуется синтезировать
неизвестные пакетные события:

- `total_messages`;
- `mtype_entropy`;
- `map_share`;
- `isup_share`;
- `in_out_ratio`.

Активность CDR не считается буквальным числом MSU. Для согласования с
каноническими шаблонами сервисов используются условные сигнальные единицы:
вызов — пять типов ISUP, исходящее SMS — одна MAP-операция, входящее SMS —
две MAP-операции.

Не наблюдаемые в агрегированном CDR зеркале признаки исключаются, а не
синтезируются: DPC-направления и их энтропия, `transit_share`,
`dlg_closure_ratio`, все кросс-узловые инварианты и `integrity_fail`.

## Калибровочный эксперимент

После первичной внешней проверки добавлен отдельный протокол калибровки на
реальном доброкачественном трафике. Реальные данные сначала делятся **строго
по времени** на непересекающиеся интервалы 60/20/20:

- 60% ранних временных интервалов — real train;
- следующие 20% — real validation;
- последние 20% — полностью отложенный real test.

Случайное перемешивание строк запрещено. При ограничении размера выборки
отбираются целые временные ряды ячеек, поэтому одна и та же временная точка
не попадает одновременно в разные части.

Сравниваются три режима:

1. `synthetic_only`: Isolation Forest и нормализация обучаются на
   синтетическом normal train, порог задаётся по synthetic validation;
2. `threshold_calibration`: модель остаётся синтетической, но порог
   задаётся по real validation;
3. `real_normal_calibration`: нормализация и Isolation Forest обучаются
   только на real train, порог задаётся по real validation, после чего
   один раз оценивается real test.

Для real-test приводится 95%-й интервал Уилсона для FPR и FPR в четырёх
последовательных временных блоках.

### Результат основного GitHub Actions прогона

Run: `45221775403`.

Использовано 117 606 реальных окон, 1 920 ячеек и 64 уникальных 10-минутных
временных интервала. Split:

- train: 69 593 окна / 38 интервалов;
- validation: 24 579 окон / 13 интервалов;
- test: 23 434 окна / 13 интервалов.

Для рекомендуемого `ratio_proxy` без абсолютного `total_messages`:

| Режим | FPR real test | 95% CI |
|---|---:|---:|
| synthetic_only | 1.809% | 1.646–1.988% |
| threshold_calibration | 0.000% | 0–0.0164% |
| real_normal_calibration | **0.111%** | **0.0757–0.1625%** |

Для `real_normal_calibration` FPR по четырём последовательным test-блокам:
0.156%, 0.0868%, 0.1215% и 0.0472%; стандартное отклонение между блоками
0.0405 процентного пункта.

Нулевой FPR режима `threshold_calibration` не следует интерпретировать как
улучшение чувствительности: у синтетического детектора на real validation
возникает дискретность/насыщение оценок, поэтому один скалярный порог становится
чрезмерно консервативным. Без реальных размеченных атак чувствительность такого
порога определить нельзя.

При включении абсолютного `total_messages` режим `real_normal_calibration`
дал 5.181% FPR на test. Это показывает выраженный временной дрейф масштаба
нагрузки и подтверждает, что для переноса между анонимизированными CDR и
модельными SS7-счётчиками предпочтительны безразмерные признаки.

Итог: калибровка на реальном доброкачественном трафике **технически
выполнима** и для безразмерного профиля существенно снижает ложные тревоги.
Однако этот эксперимент подтверждает только контроль FPR нормального трафика;
чувствительность к реальным SS7-атакам по данному набору оценить нельзя.

## Профили проверки

- `full_proxy`: пять доступных признаков, включая масштаб
  `total_messages`;
- `ratio_proxy`: четыре безразмерных признака без `total_messages`, что
  уменьшает влияние различия единиц измерения CDR и модельных счётчиков.

Для каждого профиля JSON содержит:

- `target_synthetic_fpr`;
- `synthetic_test_fpr`;
- `real_rejection_rate_unlabeled`;
- `median_ks_stat`;
- `median_real_inside_synth_99pct`;
- `median_abs_shift_sigma`;
- `transfer_warning`;
- сдвиг по каждому признаку.

`transfer_warning=true` означает существенный внешний доменный разрыв. Это
диагностика переносимости, а не оценка обнаружения реальных атак.

## Запуск

```bash
python -m ss7.validate_real_cdr \
  --date 2013-11-01 \
  --max-bytes 67108864 \
  --max-real-windows 60000 \
  --output results/ss7_real_cdr_validation.json
```
