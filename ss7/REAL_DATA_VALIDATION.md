# Внешняя проверка SS7-модели на реальных данных

## Назначение

`ss7/validate_real_cdr.py` выполняет независимую проверку внешней валидности
канонической модели ОКС-7 (`ss7/fix.py`) на **несинтетической** мобильной
нагрузке.

Исходное происхождение данных:

- Telecom Italia, **Telecommunications - SMS, Call, Internet - MI**;
- Harvard Dataverse, DOI **10.7910/DVN/EGZHFV**;
- данные получены из реальных CDR сети Telecom Italia в Милане.

Для автоматического CI используется публичное зеркало
`GreatLove/CellularTrafficPrediction` на Hugging Face. Оно уже агрегирует
исходные CDR по ячейке и времени и содержит реальные поля `sms-in`,
`sms-out`, `call-in`, `call-out`, `internet`.

Harvard Dataverse 6.10 требует Guestbook Response для прямой API-загрузки этого
набора. В CI намеренно не передаются вымышленные имя/e-mail; поэтому workflow
использует публичное зеркало с сохранением ссылки на исходный DOI и SHA-256
файла зеркала.

## Что проверяется

Публичного размеченного набора реальных SS7-атак, сопоставимого с входами
канонической модели, в открытом доступе нет. Эта проверка поэтому **не
измеряет recall, precision или AUC реальных атак** и не выдаёт CDR за
пакетную SS7-трассу.

Проверяются:

1. перенос распределений доступных признаков с нормальной синтетической
   SS7-нагрузки на независимую реальную мобильную нагрузку;
2. доля реальных окон, отвергаемых Isolation Forest как аномальные при пороге,
   откалиброванном только на нормальной синтетической validation-части;
3. величина synthetic-to-real domain shift по статистике Колмогорова—Смирнова
   и покрытию реальных значений 99%-м диапазоном синтетической нормы.

## Какие признаки восстанавливаются

Из зеркала непосредственно наблюдаются входящие/исходящие SMS и вызовы.
Поэтому используются только признаки, для которых не требуется синтезировать
неизвестные пакетные события:

- `total_messages`;
- `mtype_entropy`;
- `map_share`;
- `isup_share`;
- `in_out_ratio`.

Активность CDR не считается буквальным числом MSU. Для согласования с
каноническими шаблонами сервисов используются условные сигнальные единицы:
вызов — пять типов ISUP, исходящее SMS — одна MAP-операция, входящее SMS —
две MAP-операции.

Не наблюдаемые в агрегированном CDR зеркале признаки исключаются, а не
синтезируются: DPC-направления и их энтропия, `transit_share`,
`dlg_closure_ratio`, все кросс-узловые инварианты и `integrity_fail`.

## Калибровочный эксперимент

После первичной внешней проверки добавлен отдельный протокол калибровки на
реальном доброкачественном трафике. Реальные данные сначала делятся **строго
по времени** на непересекающиеся интервалы 60/20/20:

- 60% ранних временных интервалов — real train;
- следующие 20% — real validation;
- последние 20% — полностью отложенный real test.

Случайное перемешивание строк запрещено. При ограничении размера выборки
отбираются целые временные ряды ячеек, поэтому одна и та же временная точка
не попадает одновременно в разные части.

Сравниваются три режима:

1. `synthetic_only`: Isolation Forest и нормализация обучаются на
   синтетическом normal train, порог задаётся по synthetic validation;
2. `threshold_calibration`: модель остаётся синтетической, но порог
   задаётся по real validation;
3. `real_normal_calibration`: нормализация и Isolation Forest обучаются
   только на real train, порог задаётся по real validation, после чего
   один раз оценивается real test.

Для real-test приводится 95%-й интервал Уилсона для FPR и FPR в четырёх
последовательных временных блоках.

### Результат основного GitHub Actions прогона

Run: `45221775403`.

Использовано 117 606 реальных окон, 1 920 ячеек и 64 уникальных 10-минутных
временных интервала. Split:

- train: 69 593 окна / 38 интервалов;
- validation: 24 579 окон / 13 интервалов;
- test: 23 434 окна / 13 интервалов.

Для рекомендуемого `ratio_proxy` без абсолютного `total_messages`:

| Режим | FPR real test | 95% CI |
|---|---:|---:|
| synthetic_only | 1.809% | 1.646–1.988% |
| threshold_calibration | 0.000% | 0–0.0164% |
| real_normal_calibration | **0.111%** | **0.0757–0.1625%** |

Для `real_normal_calibration` FPR по четырём последовательным test-блокам:
0.156%, 0.0868%, 0.1215% и 0.0472%; стандартное отклонение между блоками
0.0405 процентного пункта.

Нулевой FPR режима `threshold_calibration` не следует интерпретировать как
улучшение чувствительности: у синтетического детектора на real validation
возникает дискретность/насыщение оценок, поэтому один скалярный порог становится
чрезмерно консервативным. Без реальных размеченных атак чувствительность такого
порога определить нельзя.

При включении абсолютного `total_messages` режим `real_normal_calibration`
дал 5.181% FPR на test. Это показывает выраженный временной дрейф масштаба
нагрузки и подтверждает, что для переноса между анонимизированными CDR и
модельными SS7-счётчиками предпочтительны безразмерные признаки.

Итог: калибровка на реальном доброкачественном трафике **технически
выполнима** и для безразмерного профиля существенно снижает ложные тревоги.
Однако этот эксперимент подтверждает только контроль FPR нормального трафика;
чувствительность к реальным SS7-атакам по данному набору оценить нельзя.

## Профили проверки

- `full_proxy`: пять доступных признаков, включая масштаб
  `total_messages`;
- `ratio_proxy`: четыре безразмерных признака без `total_messages`, что
  уменьшает влияние различия единиц измерения CDR и модельных счётчиков.

Для каждого профиля JSON содержит:

- `target_synthetic_fpr`;
- `synthetic_test_fpr`;
- `real_rejection_rate_unlabeled`;
- `median_ks_stat`;
- `median_real_inside_synth_99pct`;
- `median_abs_shift_sigma`;
- `transfer_warning`;
- сдвиг по каждому признаку.

`transfer_warning=true` означает существенный внешний доменный разрыв. Это
диагностика переносимости, а не оценка обнаружения реальных атак.

## Полная гибридная калибровка

Для калибровки всех доступных каналов добавлены
`ss7/calibrate_full_model.py` и workflow
`.github/workflows/ss7-full-calibration.yml`.

Под «полной» калибровкой здесь понимается калибровка всех каналов, для которых
существуют наблюдаемые данные без искусственного восстановления отсутствующих
измерений:

- **OWN-контур** калибруется на реальном доброкачественном CDR;
- **INV-контур** калибруется на канонической SS7-модели, поскольку CDR не
  содержит парных линковых, OD-, TCAP- и транзитных инвариантов;
- канал `integrity_fail` при базовом режиме `NODE_SOFTWARE` не выделяется
  в самостоятельный детектор, так как компрометированный узел владеет ключом
  отчётности.

Общий проектный бюджет FPR равен 1%. Для двух активных каналов используется
консервативное распределение Бонферрони: 0.5% для OWN и 0.5% для INV.
Объединение тревог — логическое OR; предположение о статистической независимости
каналов не требуется.

### Реальная калибровка OWN

Используются три отдельные календарные выборки Telecom Italia:

- 2013-11-01 — обучение;
- 2013-11-02 — выбор признаков/гиперпараметров и порога;
- 2013-11-03 — полностью отложенный test.

Test-день не используется при выборе конфигурации. Автоматический поиск выбрал:

- признаки: `mtype_entropy`, `map_share`, `in_out_ratio`;
- Isolation Forest: 500 деревьев, `max_samples=1024`,
  `max_features=0.75`;
- порог: 0.6462162116.

Результаты:

| Выборка | FPR | 95% ДИ Уилсона |
|---|---:|---:|
| real validation, 2013-11-02 | 0.5007% | 0.4620–0.5427% |
| real test, 2013-11-03 | **0.4811%** | **0.4432–0.5223%** |

Таким образом, OWN-контур переносит заданный бюджет 0.5% на независимый
календарный день без подстройки по test.

### Калибровка INV

В расширенном поиске сравниваются Isolation Forest, Random Forest и
механистический rule-baseline на нескольких наборах исходных, временных и
зональных инвариантов. Подбор выполняется на двух разных реализациях сети
(seeds 42 и 1337), а seed 2026 не участвует в выборе.

На текущем поиске выбран Random Forest:

- 45 признаков `inv_all_derived`;
- 400 деревьев;
- `min_samples_leaf=4`;
- `max_features="sqrt"`;
- синтетический reference-порог 0.4576354825.

На удержанной части калибровочных реализаций episode recall составил 80%.
При переносе модели и полностью замороженного порога на независимую топологию
seed 2026 episode recall составил 66.7%, однако FPR вырос до **1.390%** при
выделенном бюджете 0.5%.

Это отрицательный, но принципиально важный результат: **единственный
универсальный численный INV-порог не является переносимым между различными
топологиями/реализациями**. Поэтому значение 0.4576354825 является
синтетическим reference-порогом, а не готовым универсальным эксплуатационным
порогом. В реальной сети INV-порог должен быть откалиброван по доброкачественному
baseline этой же сети с замороженным детектором, после чего проверен на
последующем временном участке.

Полная внешняя калибровка INV на реальных данных сейчас невозможна из-за
отсутствия в публичном CDR необходимых межузловых SS7-счётчиков. Искусственно
восстанавливать их из CDR нельзя: это превратило бы независимую внешнюю
калибровку в синтетический эксперимент.

### Статус полной модели

На текущих данных:

1. реальный OWN-контур **полностью откалиброван по FPR** и подтверждён на
   независимом дне;
2. структура и модель INV-контурa откалиброваны и проверены между
   синтетическими реализациями, но **универсальный INV-порог отвергнут** по
   результату независимого seed;
3. для завершения именно реальной калибровки всей модели требуются
   доброкачественные MTP3/MAP/TCAP/OD/транзитные счётчики конкретной сети;
4. реальная чувствительность к атакам остаётся неизмеримой без независимых
   размеченных SS7-атак.



## Полная проверка детекторов на откалиброванной имитационной модели

После калибровки выполнены два независимых GitHub Actions эксперимента:

- multiseed validation: run `45237409478`;
- controlled stress validation: run `45237409456`.

Используемый код в этих успешных прогонах побитно совпадает с текущими
`ss7/validate_calibrated_detectors.py` и
`ss7/validate_calibrated_stress.py`.

### Нулевой тест

Контрфактуальный тест при скрытой активности `h=0` пройден:

- максимальное расхождение наблюдаемых признаков между компрометированным
  `h=0` и честным миром: **0**;
- диагностический AUC для SP: **0.500**,
  95% ДИ 0.477–0.525;
- диагностический AUC для STP: **0.500**,
  95% ДИ 0.456–0.544;
- energy-test: `p=1.0`;
- все проверенные признаки эквивалентны.

Следовательно, генератор не содержит тривиальной подписи факта компрометации,
не связанной со скрываемой активностью.

### Межтопологическая multiseed-проверка

Пять seed (`42, 1337, 2026, 7, 31415`) независимо регенерируют топологию и
трафик. Разбиение — блочное временное с purge-зазором. Численные пороги
выбираются только по validation-негативам каждой реализации; test не
используется для настройки.

| Детектор | Episode recall, среднее | AUC | AP | Test FPR, среднее | Max test FPR |
|---|---:|---:|---:|---:|---:|
| rule baseline | 10.0% | 0.600 | 0.104 | 0.926% | 1.755% |
| calibrated OWN IF | **0.0%** | 0.540 | 0.112 | 0.569% | 1.884% |
| Isolation Forest, OWN+INV | 40.0% | 0.847 | 0.395 | 1.445% | 4.683% |
| calibrated INV RF | 43.3% | 0.841 | 0.505 | **0.900%** | 1.668% |
| calibrated hybrid OWN OR INV | 43.3% | 0.790 | 0.491 | 1.426% | 2.984% |
| Random Forest, OWN+INV | **66.7%** | **0.862** | **0.527** | 1.707% | 3.453% |

Полный Random Forest имеет наибольшую среднюю чувствительность, но не удерживает
целевой FPR=1% на последующем test. Откалиброванный INV RF хуже по recall, зато
лучше сохраняет эксплуатационный бюджет ложных тревог.

Ключевой отрицательный результат: OWN IF на синтетических компрометациях не
обнаружил ни одного эпизода. Его добавление к INV через OR не увеличило episode
recall (43.3% против 43.3% у INV), но увеличило средний test FPR с 0.900% до
1.426%. Поэтому OWN-контур нельзя считать доказанным каналом обнаружения
скрытой компрометации; на текущих данных он полезен прежде всего как
реально-калиброванный канал контроля структуры/дрейфа нагрузки.

### Ложные тревоги на доброкачественных эксплуатационных событиях

Для гибридного детектора получены следующие частоты тревог:

| Контекст | Доля тревог |
|---|---:|
| обычный фон | 1.31% |
| traffic spike | **24.15%** |
| campaign | **10.33%** |
| traffic dip | 7.00% |
| link failure | 5.38% |
| reroute | 4.12% |
| scale in | 0.00% |

Таким образом, traffic spike и campaign являются сильными негативными
контролями: текущий гибридный детектор недостаточно отделяет их от
компрометации. Это ограничение должно учитываться при дальнейшем выборе
архитектуры и при формулировке результатов диссертации.

### Stress-проверка по интенсивности

На фиксированной топологии с независимыми traffic/adversary seed и замороженными
порогами гибрид показал:

| Скрытая интенсивность | Episode recall | AUC | Median TTD |
|---:|---:|---:|---:|
| 0.05 | 41.7% | 0.620 | 2460 с |
| 0.15 | 75.0% | 0.739 | 1290 с |
| 0.40 | **91.7%** | 0.955 | 120 с |
| 1.00 | 83.3% | 0.950 | 165 с |
| 2.50 | 91.7% | 0.932 | 840 с |

Самый трудный режим — низкоинтенсивный `h=0.05`. Зависимость не строго
монотонна, поскольку уровни проверялись на независимых реализациях; поэтому
таблица используется как stress-проверка, а не как причинная оценка влияния
одного только параметра `h`.

### Stress-проверка по семействам маскировки

| Семейство | Episode recall | AUC | Median TTD |
|---|---:|---:|---:|
| F1 uniform | 91.7% | 0.960 | 90 с |
| F2 single link | **58.3%** | 0.844 | 660 с |
| F3 proportional | 91.7% | 0.827 | 480 с |
| F4 temporal | 72.7% | 0.795 | 135 с |

Наиболее трудными по episode recall являются F2 и F5.

### Гарантированный leave-one-masking-family-out

INV Random Forest обучался без конкретного семейства, после чего проверялся на
отдельном мире, содержащем только это ранее не виденное семейство:

- F1: recall 91.7%, AUC 0.905;
- F2: recall 50.0%, AUC 0.874;
- F3: recall 66.7%, AUC 0.739;
- F4: recall 63.6%, AUC 0.760;
- F5: recall 58.3%, AUC 0.737.

Следовательно, детектор способен частично переноситься на неизвестный способ
маскировки, но устойчивость неоднородна и особенно недостаточна для F2/F5.

### Итог проверки

Полная проверка **не подтверждает**, что текущий гибрид является окончательной
архитектурой детектора. Подтверждены:

1. отсутствие искусственной подписи компрометации при `h=0`;
2. информативность кросс-узлового INV-контура;
3. преимущество ML над простым rule baseline;
4. способность обнаруживать часть ранее не виденных семейств маскировки.

Одновременно выявлены ограничения:

1. OWN IF не добавляет чувствительности к моделируемой скрытой компрометации;
2. OR-fusion OWN+INV повышает FPR без прироста episode recall;
3. полный RF чувствительнее INV RF, но хуже удерживает FPR между временными
   блоками/топологиями;
4. доброкачественные traffic spike и campaign вызывают высокий уровень тревог;
5. низкоинтенсивный режим `h=0.05` остаётся наиболее сложным;
6. численный порог требует локальной validation-калибровки и не должен
   переноситься как универсальная константа.

Эти результаты являются основанием для следующей архитектурной итерации:
разделить каналы обнаружения компрометации и контроля дрейфа, а также добавить
явное подавление тревог для доброкачественных режимов spike/campaign.


## Архитектурная итерация после полной проверки

### Контекстный порог по OWN-признакам

Проверена схема, в которой INV Random Forest остаётся единственным каналом
атаки, а OWN Random Forest классифицирует доброкачественный контекст
(`load_surge`, `load_reduction`, `link_failure`, `reroute`).
Для уверенно распознанного контекста предполагалось только повышать INV-порог.

Успешный GitHub Actions run: `45258599122`.

На пяти новых seed 6001–6005 контекстная модификация не дала измеримого
улучшения относительно глобального INV-порога:

- episode recall: 58.3% в обоих вариантах;
- средний window FPR: 2.592% в обоих вариантах;
- AUC: 0.840 в обоих вариантах.

Причина диагностирована непосредственно: в validation для большинства
доброкачественных контекстов не набиралось достаточного числа уверенно
распознанных окон, поэтому контекстные пороги фактически совпадали с глобальным.
Эта схема отвергнута как практически неэффективная.

### Двухкаскадный hard-negative детектор

Следующая схема использует:

1. первый каскад — INV Random Forest, формирующий evidence-score;
2. второй каскад — Random Forest по OWN-производным признакам и INV-score;
3. второй каскад обучается на всех атаках и только верхних 10% наиболее
   «трудных» нормальных окон по INV-score;
4. итоговый score = `INV_probability × suppressor_attack_probability`;
5. модельные веса обучаются на development seeds, а численный порог
   определяется только по validation-негативам целевой реализации.

Первичный screening run: `45352131619` (seeds 7101–7103).

| Детектор | Episode recall | FPR | AUC | AP |
|---|---:|---:|---:|---:|
| INV RF | 38.9% | 2.386% | 0.683 | 0.458 |
| Full RF | 83.3% | 2.762% | 0.991 | 0.943 |
| Two-stage INV+OWN | **83.3%** | **3.166%** | 0.920 | 0.581 |

Положительный результат screening: для двухкаскадного детектора на этой
выборке `traffic_spike` и `campaign` дали **0% ложных тревог**, тогда как
rule-baseline давал соответственно 10.7% и 78.6%.

Отрицательный результат: общий FPR 3.166% существенно выше проектного 1%.
Это означает, что hard-negative архитектура решает проблему специальных
доброкачественных режимов, но не решает временной перенос численного порога.

Поэтому до просмотра пяти финальных seed 7001–7005 заранее зафиксировано
следующее правило устойчивой калибровки порога:

`threshold = max(global validation q99, q99 по каждому из 4 последовательных validation-блоков)`.

Test-данные не участвуют в выборе этого правила. Одновременно сохраняется
обычный q99 как контроль, что позволит отдельно оценить эффект именно
temporal-robust калибровки.
